# Диаграмма интеграции C# MediaMonitor

## Простая схема работы

```
┌─────────────────────────────────────────────────────────────┐
│                    Windows Media Players                     │
│         (Spotify, iTunes, VLC, Chrome, и др.)               │
└────────────────────────┬────────────────────────────────────┘
                         │
                         │ Windows Media Control API
                         │
                         ▼
        ┌────────────────────────────────────┐
        │     C# MediaMonitor.exe            │
        │                                    │
        │  • Отслеживание треков             │
        │  • Загрузка обложек                │
        │  • Получение метаданных            │
        └────────────┬───────────────────────┘
                     │
                     │ HTTP POST
                     │ /update_from_cs
                     │
                     ▼
        ┌────────────────────────────────────┐
        │     Python Server (now.py)         │
        │     http://localhost:80            │
        │                                    │
        │  • Прием данных от C#              │
        │  • WebSocket сервер                │
        │  • HTTP API                        │
        └────────────┬───────────────────────┘
                     │
                     │ WebSocket
                     │ ws://localhost:80/ws
                     │
                     ▼
        ┌────────────────────────────────────┐
        │         Web Clients                │
        │                                    │
        │  • Браузер                         │
        │  • OBS Browser Source              │
        │  • Другие WebSocket клиенты        │
        └────────────────────────────────────┘
```

## Поток данных при смене трека

```
1. Пользователь переключает трек в Spotify
   │
   ▼
2. Windows Media API уведомляет C# MediaMonitor
   │
   ▼
3. C# MediaMonitor:
   ├─ Получает название и исполнителя
   ├─ Загружает обложку → songinfo/cover.png
   └─ Получает длительность трека
   │
   ▼
4. C# отправляет HTTP POST на Python сервер:
   {
     "artist": "Artist Name",
     "title": "Track Title",
     "position": 0,
     "duration": 180,
     "is_playing": true,
     "cover_version": 1,
     "status": "active"
   }
   │
   ▼
5. Python сервер:
   ├─ Обновляет глобальное состояние
   └─ Рассылает обновление всем WebSocket клиентам
   │
   ▼
6. Веб-клиенты получают обновление:
   {
     "type": "update",
     "data": {
       "artist": "Artist Name",
       "title": "Track Title",
       "cover_url": "/cover?v=1",
       ...
     }
   }
   │
   ▼
7. Браузер/OBS обновляет отображение
```

## Сравнение режимов

### Режим 1: Только Python (по умолчанию)

```
Windows Media API → Python (winsdk) → WebSocket → Клиенты
```

**Плюсы:**
- ✅ Не требует C# / .NET
- ✅ Все в одном процессе
- ✅ Простая настройка

**Минусы:**
- ❌ Медленнее реакция на смену треков
- ❌ Больше нагрузка на CPU
- ❌ Зависимость от winsdk

### Режим 2: C# + Python (рекомендуется)

```
Windows Media API → C# MediaMonitor → HTTP → Python → WebSocket → Клиенты
```

**Плюсы:**
- ✅ Быстрая реакция на смену треков
- ✅ Меньше нагрузка на CPU
- ✅ Нативная работа с Windows API
- ✅ Более стабильная работа

**Минусы:**
- ❌ Требует .NET 6.0+
- ❌ Два процесса вместо одного
- ❌ Немного сложнее настройка

│                      Python Server                           │

## Последовательность запуска

### Автоматический запуск (start_media_monitor.bat)

```
1. Запуск Python сервера
   └─ python main.py
      └─ Сервер слушает на http://localhost:80

2. Ожидание 3 секунды (для инициализации сервера)

3. Запуск C# MediaMonitor
   └─ cd MediaMonitor && dotnet run
      └─ Подключение к http://localhost:80

4. Готово! Оба компонента работают
```

### Ручной запуск

```
Терминал 1:
$ python main.py
🚀 Сервер запущен: http://localhost:80

Терминал 2:
$ cd MediaMonitor
$ dotnet run
✅ MediaMonitor запущен!
🎵 Новый трек: Artist - Title
```

```
C# MediaMonitor
    │
    ├─ Попытка отправки на Python сервер
    │
    ├─ Успех? ──────────────────────────┐
    │                                    │
    │                                    ▼
    │                            Python обрабатывает
    │                                    │
    │                                    ▼
    │                            Рассылка клиентам
    │
    └─ Ошибка? ─────────────────────────┐
                                        │
                                        ▼
                            ⚠️ Логирование ошибки
                            (не прерывает работу)
                                        │
                                        ▼
                            Следующая попытка через 1 сек
```

## Оптимизации

### Троттлинг обновлений

```
Обновление 1 ──┐
               │ < 100ms
Обновление 2 ──┤ ❌ Пропущено
               │
               │ > 100ms
Обновление 3 ──┘ ✅ Отправлено
```

### Асинхронная обработка треков

```
Новый трек обнаружен
    │
    ├─────────────────────────────┐
    │                             │
    ▼                             ▼
Немедленная отправка      Фоновая задача:
базовых данных            ├─ Загрузка обложки
    │                     └─ Получение длительности
    │                             │
    │                             ▼
    └──────────────┬──────────────┘
                   │
                   ▼
        Финальное обновление
        с полными данными
```

## Масштабирование

### Текущая архитектура (1 сервер)

```
C# MediaMonitor → Python Server → N WebSocket клиентов
```

### Возможная архитектура (распределенная)

```
                    ┌─ Python Server 1 → Клиенты 1-100
                    │
C# MediaMonitor → Redis → Python Server 2 → Клиенты 101-200
                    │
                    └─ Python Server 3 → Клиенты 201-300
```
