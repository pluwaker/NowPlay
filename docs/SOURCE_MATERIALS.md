# ИСХОДНЫЕ МАТЕРИАЛЫ ИЗ ПРОЕКТА NOWPLAY

---

## 1. ОБЩАЯ ИНФОРМАЦИЯ О ПРОЕКТЕ

### Название проекта
**NowPlay** - Виджет для отображения текущего трека в OBS Studio

### Полное название для ТЗ
"Разработка кроссплатформенной системы управления и визуализации мультимедийного контента для стриминговых сервисов"

### Краткое описание
Современное десктопное приложение для Windows, которое отображает информацию о текущем воспроизводимом треке прямо в OBS Studio. Приложение работает через локальный веб-сервер, что позволяет легко интегрировать виджет в любой стрим или запись.

---

## 2. ОСНОВНЫЕ ВОЗМОЖНОСТИ

1. **Автоматическое определение трека** из медиаплееров Windows
2. **Автоматическое получение обложек** из Last.fm, iTunes, Yandex Music и VK Music
3. **Настраиваемые шаблоны** визуализации (4 различных варианта)
4. **Гибкая настройка цветов** подложки, акцентов и элементов интерфейса
5. **Автоматические цвета** на основе обложки альбома
6. **Отображение прогресса** воспроизведения с возможностью перемотки
7. **Анимированный визуализатор** с настраиваемыми параметрами
8. **Подсветка обложки** (ambient light) с автоматической цветовой палитрой
9. **Гибкое позиционирование** виджета на экране
10. **WebSocket** для обновления данных в реальном времени

## 4. АРХИТЕКТУРА СИСТЕМЫ

### Трёхуровневая архитектура

**Уровень 1: Desktop Application**
- GUI на базе CustomTkinter
- Управление настройками
- Запуск/остановка сервера
- Модули: main.py, ui/app.py, ui/pages/

**Уровень 2: Web Server**
- HTTP сервер на aiohttp
- WebSocket для обновлений в реальном времени
- API для получения информации о треке
- Модули: now_server/now.py, now_server/cover_fetcher.py

**Уровень 3: Frontend Widgets**
- HTML/CSS/JavaScript виджеты
- 4 шаблона визуализации
- Canvas API для извлечения цветов
- Файлы: visualisation*.html, common.js

### C# MediaMonitor (опциональный компонент)
- Нативная работа с Windows Media Control API
- Быстрее реагирует на смену треков
- Меньше нагрузка на CPU
- Автоматическая отправка данных на Python сервер

## 8. РЕЗУЛЬТАТЫ ОПТИМИЗАЦИИ

### Проблема
Высокая нагрузка CPU при извлечении цветов из обложек: 20-35%

### Решение
1. Уменьшение размера canvas с 200x200 до 80x80 пикселей
2. Увеличение шага выборки пикселей с 32 до 128 байт
3. Упрощение алгоритма выбора цветов
4. Добавление кэширования результатов (Map)
5. Реализация дебаунсинга (300ms) для быстрых переключений

### Результаты
- **Нагрузка CPU:** снижена с 20-35% до 0.8-2%
- **Время обработки изображения:** с 150ms до 20ms
- **Использование памяти:** стабильно < 200 МБ
- **Стабильность:** 48+ часов непрерывной работы

## 10. API ENDPOINTS

### HTTP Endpoints
- `POST /update_from_cs` - Получение данных от C# MediaMonitor
- `GET /cover?v={version}` - Получение обложки
- `GET /ws` - WebSocket соединение
- `POST /update_config` - Обновление конфигурации
- `GET /sources` - Список доступных источников медиа

### WebSocket Messages
```json
{
  "type": "update" | "init" | "config_update",
  "data": {
    "artist": "string",
    "title": "string",
    "position": 0.0,
    "duration": 0.0,
    "is_playing": true,
    "cover_url": "/cover?v=1",
    "status": "active" | "inactive"
  }
}
```

## 12. КЛЮЧЕВЫЕ АЛГОРИТМЫ

### Алгоритм извлечения цветов
1. Загрузка изображения в canvas (80x80px)
2. Получение данных пикселей
3. Выборка пикселей с шагом 128 байт
4. Группировка похожих цветов
5. Фильтрация серых и темных цветов
6. Выбор контрастных цветов
7. Кэширование результата

### Алгоритм получения обложек
1. Приоритизация источников (Last.fm → iTunes → Yandex → VK)
2. Попытка получения от каждого источника
3. Обработка ошибок (timeout, 404)
4. Fallback на дефолтную обложку
5. Кэширование результата

### Алгоритм мониторинга медиа
1. Опрос Windows Media API каждую секунду
2. Сравнение artist/title с предыдущим состоянием
3. При изменении: параллельная загрузка обложки и получение длительности
4. Отправка данных на Python сервер
5. Рассылка обновлений по WebSocket
