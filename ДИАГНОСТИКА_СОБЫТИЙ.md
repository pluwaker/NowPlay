# 🔍 Диагностика проблемы: "Отправляет один раз, потом нет"

## Быстрая диагностика

### Шаг 1: Запустите тестовый сервер

```bash
python test_mediamonitor_events.py
```

Вы увидите:
```
🧪 ТЕСТОВЫЙ СЕРВЕР ДЛЯ MEDIAMONITOR
🚀 Сервер запущен на http://localhost:58080
⏳ Ожидаем подключения MediaMonitor...
```

### Шаг 2: Запустите MediaMonitor в диагностическом режиме

```bash
cd MediaMonitor\bin\Release\net6.0-windows10.0.19041.0
.\MediaMonitor.exe --diagnostic
```

### Шаг 3: Включите музыку

Включите любой медиа-плеер (Spotify, iTunes, YouTube и т.д.)

### Шаг 4: Наблюдайте за выводом

**В тестовом сервере вы должны увидеть:**
```
📥 Обновление #1 получено в 19:30:45.123
🎵 Artist - Title
▶️  Позиция: 0.0s | Играет: true
✅ Первое обновление получено!
⏳ Ожидаем следующие обновления...
```

**В MediaMonitor вы должны увидеть:**
```
✅ MediaMonitor запущен!
🔗 Подключение к серверу: http://localhost:58080
📥 EventSubscriptionManager: Subscribing to session: Spotify
  ✅ Subscribed to MediaPropertiesChanged
  ✅ Subscribed to PlaybackInfoChanged
  ✅ Subscribed to TimelinePropertiesChanged
✅ EventSubscriptionManager: All subscriptions established
🎵 Artist - Title
✅ Update sent to Python server
```

### Шаг 5: Смените трек или нажмите play/pause

**Если всё работает правильно:**

Тестовый сервер покажет:
```
📥 Обновление #2 получено в 19:31:15.456
🎵 New Artist - New Title
```

MediaMonitor покажет:
```
🎵 Event: MediaPropertiesChanged at 19:31:15.456
  - New Artist - New Title
  ⏱ Handler execution time: 15ms
✅ Update sent to Python server
```

**Если обновления НЕ приходят:**

Тестовый сервер покажет:
```
⚠️  Обновлений не было 10 секунд
   Попробуйте сменить трек или нажать play/pause
```

Через 30 секунд:
```
❌ ПРОБЛЕМА: Обновлений не было 30 секунд!
   MediaMonitor должен был запустить восстановление
```

MediaMonitor должен показать:
```
[HEALTH] Heartbeat check: Last update 30 seconds ago
[HEALTH] Timeout detected: No updates for 30 seconds
🔄 Запуск процедуры восстановления...
[RECOVERY] Initiating recovery procedure (attempt 1/3)
[RECOVERY] Unsubscribing from all events
[RECOVERY] Reinitializing session manager
[RECOVERY] Reestablishing event subscriptions
[RECOVERY] Recovery completed successfully
```

## Возможные проблемы и решения

### Проблема 1: События вообще не срабатывают

**Симптомы:**
- Первое обновление приходит
- Дальше ничего не происходит
- В MediaMonitor нет сообщений о событиях

**Причина:** Windows Media API не отправляет события

**Решение:**
1. Перезапустите медиа-плеер
2. Перезапустите MediaMonitor
3. Попробуйте другой медиа-плеер (Spotify, iTunes, VLC)

### Проблема 2: Восстановление не срабатывает

**Симптомы:**
- Обновления прекратились
- Прошло более 30 секунд
- Нет сообщений о восстановлении

**Причина:** HealthMonitor не запущен или не работает

**Решение:**
Проверьте код в `MediaMonitor.cs`:
```csharp
// Должно быть в методе Start():
healthMonitor = new HealthMonitor();
healthMonitor.RecoveryNeeded += OnRecoveryNeeded;
healthMonitor.Start();  // ← Это критично!
```

### Проблема 3: Восстановление срабатывает, но не помогает

**Симптомы:**
- Видны сообщения о восстановлении
- Но обновления всё равно не приходят

**Причина:** Windows Media API полностью "отвалился"

**Решение:**
1. Перезапустите MediaMonitor
2. Перезапустите медиа-плеер
3. Перезагрузите компьютер (в крайнем случае)

### Проблема 4: UpdateQueue блокируется

**Симптомы:**
- События срабатывают (видны в консоли)
- Но обновления не отправляются на сервер

**Причина:** Блокировка в UpdateQueue

**Решение:**
Проверьте логи на наличие:
```
[LOCK] Timeout acquiring update lock
```

Если видите такие сообщения, это проблема с блокировками.

## Проверка компонентов

### 1. HealthMonitor

```bash
# В консоли MediaMonitor должны быть сообщения каждые 5 секунд:
[HEALTH] Heartbeat check: Last update 3 seconds ago (healthy)
```

Если таких сообщений нет - HealthMonitor не запущен!

### 2. EventSubscriptionManager

```bash
# При старте должны быть:
📥 EventSubscriptionManager: Subscribing to session: Spotify
  ✅ Subscribed to MediaPropertiesChanged
  ✅ Subscribed to PlaybackInfoChanged
  ✅ Subscribed to TimelinePropertiesChanged
```

### 3. UpdateQueue

```bash
# При каждом обновлении должно быть:
[QUEUE] Update queued
[QUEUE] Processing update
✅ Update sent to Python server
```

### 4. RecoveryManager

```bash
# При таймауте должно быть:
🔄 Запуск процедуры восстановления...
[RECOVERY] Initiating recovery procedure (attempt 1/3)
```

## Логи

Если запущен диагностический режим, проверьте файл:
```
MediaMonitor/logs/mediamonitor_YYYYMMDD_HHMMSS.log
```

Там будет полная информация о всех событиях.

## Статус тестового сервера

Откройте в браузере:
```
http://localhost:58080/status
```

Вы увидите JSON с информацией о полученных обновлениях.
