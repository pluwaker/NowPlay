# ❓ FAQ - Часто задаваемые вопросы

## Общие вопросы

### Что такое MediaMonitor?

MediaMonitor - это система для отображения информации о текущем воспроизводимом треке в Windows. Состоит из двух компонентов:
- **Python сервер** - веб-сервер с WebSocket для отображения в браузере/OBS
- **C# MediaMonitor** (опционально) - нативное приложение для мониторинга Windows Media

### Зачем нужна C# интеграция?

C# интеграция предоставляет:
- ⚡ Более быструю реакцию на смену треков
- 💪 Меньшую нагрузку на CPU
- 🎯 Более стабильную работу с Windows Media API
- 🚀 Лучшую производительность в целом

### Обязательно ли использовать C# компонент?

Нет! C# интеграция полностью опциональна. Вы можете использовать только Python сервер, который имеет встроенный мониторинг через `winsdk`.

## Установка и настройка

### Какие требования для C# MediaMonitor?

- Windows 10/11
- .NET 6.0 или выше
- Python сервер должен быть запущен

### Как установить .NET?

Скачайте и установите .NET SDK с официального сайта:
https://dotnet.microsoft.com/download

### Как запустить оба компонента?

**Самый простой способ:**
```bash
start_media_monitor.bat
```

**Или вручную:**
```bash
# Терминал 1
python main.py

# Терминал 2
cd MediaMonitor
dotnet run
```

### Как изменить порт сервера?

**Начиная с последней версии, порт передается автоматически!**

MediaMonitor теперь автоматически получает правильный порт от Python приложения. Если порт 8080 занят, система автоматически найдет свободный порт и передаст его в MediaMonitor.

**Для ручного запуска MediaMonitor с кастомным портом:**
```bash
MediaMonitor.exe --port 58081
# или
MediaMonitor.exe -p 58081
```

**Примечание:** Порт по умолчанию изменен с 8080 на 58080 для избежания конфликтов.

**Для изменения стартового порта в Python:**
```python
# В ui/app.py
def find_free_port(start_port=58080, max_port=59000):  # Измените start_port
```

### Как отключить встроенный Python мониторинг?

Добавьте в конфигурацию:
```json
{
  "use_builtin_monitor": false
}
```

Это рекомендуется при использовании C# MediaMonitor для избежания конфликтов.

## Работа с треками

### Почему не отображается текущий трек?

**Возможные причины:**

1. **Медиаплеер не поддерживается**
   - Убедитесь, что плеер использует Windows Media Control API
   - Попробуйте Spotify, VLC, или Windows Media Player

2. **Сервер не запущен**
   - Проверьте, что Python сервер работает
   - Откройте http://localhost:58080 в браузере

3. **C# MediaMonitor не подключен**
   - Проверьте консоль C# на наличие ошибок
   - Убедитесь, что URL сервера правильный

4. **Источники не обнаружены**
   - Подождите 3-4 секунды после запуска MediaMonitor
   - MediaMonitor автоматически повторяет поиск источников
   - См. [SOURCES_DETECTION_FIX.md](SOURCES_DETECTION_FIX.md) для деталей

### Как выбрать конкретный источник медиа?

В конфигурации укажите:
```json
{
  "selected_media_source": "Spotify.exe"
}
```

Или используйте endpoint `/sources` для получения списка доступных источников.

### Почему трек меняется с задержкой?

**Если используете Python мониторинг:**
- Это нормально, задержка ~1-2 секунды
- Используйте C# MediaMonitor для более быстрой реакции

**Если используете C# MediaMonitor:**
- Задержка должна быть минимальной (<500ms)
- Проверьте нагрузку на CPU
- Убедитесь, что `use_builtin_monitor: false`

## Обложки

### Почему не загружается обложка?

**Возможные причины:**

1. **Нет интернета**
   - Обложки загружаются из Last.fm, iTunes, и других API
   - Проверьте подключение к интернету

2. **Трек не найден в базах**
   - Редкие треки могут отсутствовать
   - Попробуйте другой источник обложек

3. **Ошибка сохранения**
   - Проверьте права доступа к папке `songinfo/`
   - Убедитесь, что папка существует

### Где хранятся обложки?

Обложки сохраняются в папке `songinfo/cover.png` относительно корня проекта.

### Как очистить кэш обложек?

Просто удалите файлы из папки `songinfo/`:
```bash
del songinfo\*.png
```

## Производительность

### Высокая нагрузка на CPU

**Решения:**

1. **Используйте C# MediaMonitor**
   ```json
   {
     "use_builtin_monitor": false
   }
   ```

2. **Отключите визуализатор**
   ```json
   {
     "wave_enabled": false
   }
   ```

3. **Отключите ambient light**
   - Уберите эффект подсветки обложки

4. **Используйте более простой шаблон**
   - Попробуйте `visualisation_var3.html`

### Задержки при обновлении

**Проверьте:**

1. **Троттлинг работает правильно**
   - Минимальный интервал: 100ms
   - Не изменяйте без необходимости

2. **Нет накопления мертвых WebSocket соединений**
   - Периодическая очистка происходит автоматически
   - Проверьте консоль сервера

3. **Не запущено несколько экземпляров**
   - Убедитесь, что запущен только один Python сервер
   - Убедитесь, что запущен только один C# MediaMonitor

## Интеграция с OBS

### Как добавить виджет в OBS?

1. Добавьте источник **Browser Source**
2. URL: `http://localhost:80/visualisation.html`
3. Ширина: 900px (или по желанию)
4. Высота: 900px (или по желанию)
5. ✅ Отметьте "Shutdown source when not visible"

### Виджет не отображается в OBS

**Проверьте:**

1. **Сервер запущен**
   - Откройте URL в обычном браузере
   - Должна отображаться информация о треке

2. **URL правильный**
   - Скопируйте точный URL из приложения
   - Убедитесь, что порт совпадает

3. **OBS Browser Source настроен**
   - Проверьте размеры (ширина/высота)
   - Попробуйте перезапустить источник

### Виджет отображается, но не обновляется

**Проверьте:**

1. **WebSocket подключен**
   - Откройте консоль браузера (F12)
   - Должно быть сообщение "WebSocket подключен"

2. **Трек воспроизводится**
   - Убедитесь, что музыка играет
   - Попробуйте переключить трек

3. **Нет ошибок в консоли**
   - Проверьте консоль браузера на ошибки
   - Проверьте консоль Python сервера

## Разработка и API

### Как отправить данные на сервер программно?

**Python:**
```python
import requests

data = {
    "artist": "Artist Name",
    "title": "Track Title",
    "position": 0,
    "duration": 180,
    "is_playing": True,
    "cover_version": 1,
    "status": "active"
}

requests.post("http://localhost:80/update_from_cs", json=data)
```

**JavaScript:**
```javascript
fetch("http://localhost:80/update_from_cs", {
    method: "POST",
    headers: {"Content-Type": "application/json"},
    body: JSON.stringify(data)
});
```

Больше примеров в [API_EXAMPLES.md](docs/API_EXAMPLES.md)

### Как подключиться к WebSocket?

**JavaScript:**
```javascript
const ws = new WebSocket("ws://localhost:80/ws");

ws.onmessage = (event) => {
    const message = JSON.parse(event.data);
    console.log(message);
};
```

**Python:**
```python
import asyncio
import websockets

async def listen():
    async with websockets.connect("ws://localhost:80/ws") as ws:
        async for message in ws:
            print(message)

asyncio.run(listen())
```

### Как получить список источников медиа?

```bash
curl http://localhost:80/sources
```

Или в JavaScript:
```javascript
fetch("http://localhost:80/sources")
    .then(r => r.json())
    .then(data => console.log(data.sources));
```

## Ошибки и отладка

### MediaMonitor не получает данные от сервера

**Симптомы:**
- Сервер запущен на порту 8081 (или другом)
- MediaMonitor пытается подключиться к 8080
- Нет обновлений треков

**Решение:**

Это было исправлено в последней версии! Теперь порт передается автоматически.

**Если проблема осталась:**

1. **Пересоберите MediaMonitor.exe:**
   ```bash
   cd MediaMonitor
   dotnet build -c Release
   ```

2. **Проверьте, что используется новая версия:**
   - В консоли должно быть: `🔌 Using port: XXXX`
   - Порт должен совпадать с портом Python сервера

3. **Убедитесь, что MediaMonitor запускается через Python приложение**
   - Не запускайте MediaMonitor.exe вручную (если не указываете порт)

См. [PORT_CONFIGURATION_FIX.md](PORT_CONFIGURATION_FIX.md) для деталей.

### "Порт 8080 занят"

**Решение:**

**Начиная с последней версии, это больше не проблема!**

Система автоматически найдет свободный порт (58080, 58081, 58082...) и передаст его в MediaMonitor. Вы увидите в консоли:
```
✅ Сервер запущен на http://localhost:58080
✅ MediaMonitor started (PID: 12345, Port: 58080)
```

**Примечание:** Порт по умолчанию изменен с 8080 на 58080 для избежания конфликтов.

**Примечание:** Порт по умолчанию изменен с 8080 на 58080 для избежания конфликтов.

**Если все равно возникают проблемы:**

1. **Найдите процесс, использующий порты:**
   ```bash
   netstat -ano | findstr :5808
   ```

2. **Остановите ненужные процессы или перезапустите приложение**

### "Python сервер недоступен"

**Проверьте:**

1. **Сервер запущен:**
   ```bash
   curl http://localhost:80
   ```

2. **Нет ошибок в консоли Python**

3. **Firewall не блокирует соединение**

### "Ошибка сохранения обложки"

**Проверьте:**

1. **Права доступа к папке `songinfo/`**
2. **Папка существует**
3. **Достаточно места на диске**

### Как включить подробное логирование?

**В C# MediaMonitor:**
- Все логи выводятся в консоль автоматически

**В Python сервере:**
- Добавьте `print()` в нужных местах
- Или используйте модуль `logging`

## Дополнительные вопросы

### Можно ли использовать на macOS/Linux?

**Python сервер:** Теоретически да, но требует адаптации (Windows Media API специфичен для Windows)

**C# MediaMonitor:** Нет, использует Windows-специфичные API

### Можно ли использовать удаленно?

Да, но требуется:
- Изменить `localhost` на IP адрес сервера
- Настроить firewall
- Рекомендуется добавить HTTPS и аутентификацию
