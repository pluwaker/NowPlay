# <a name="_введение"></a>**1. Введение**

## <a name="_наименование"></a>**1.1 Наименование и область применения**

NowPlay — система управления и визуализации мультимедийного контента для стриминговых сервисов, представляющая собой комплексное программное решение для автоматического отображения информации о текущем воспроизводимом музыкальном треке непосредственно в прямых трансляциях и видеозаписях.

## <a name="_характеристика"></a>**1.2 Краткая характеристика области применения программы**

Программный продукт предназначен для стримеров на платформах Twitch и YouTube Gaming, контент-криейторов, создающих видеоконтент для различных платформ, пользователей программного обеспечения для стриминга (OBS Studio, Streamlabs OBS), музыкальных блогеров и обозревателей, создателей подкастов и аудиоконтента. Система применяется в прямых трансляциях, записи видеоконтента с отображением информации о воспроизводимой музыке, создании музыкальных шоу и подкастов, интеграции музыкального контента в игровые стримы.

**Принцип работы и технологическая платформа.**

Система осуществляет непрерывный мониторинг активных медиаплееров на компьютере пользователя через Windows Media Control API с частотой опроса один раз в секунду. При обнаружении воспроизведения музыки программа автоматически извлекает метаданные трека (исполнитель, название, альбом, длительность, текущая позиция воспроизведения) и инициирует загрузку обложки альбома из множественных источников с интеллектуальной приоритизацией. Поддерживаются все популярные медиаплееры: Spotify, Apple Music, YouTube Music, VLC Media Player, Windows Media Player, Groove Music, а также веб-браузеры при воспроизведении музыки на веб-сайтах.

Информация отображается через настраиваемые веб-виджеты, интегрируемые в OBS Studio через Browser Source. Предоставляется четыре профессиональных шаблона визуализации, оптимизированных для различных сценариев. Все шаблоны поддерживают автоматическое извлечение доминирующих цветов из обложки альбома для создания гармоничной цветовой палитры, Ambient Light эффект, плавные CSS анимации и прозрачный фон для наложения на любой контент.

Система построена на гибридной архитектуре: Backend реализован на Python 3.12+ с использованием асинхронного веб-сервера aiohttp 3.8+, библиотеки CustomTkinter 5.0+ для создания современного графического интерфейса. Компонент мониторинга медиаплееров разработан на C# .NET 6.0+ с использованием Windows Media Control API, что обеспечивает высокую производительность и нативную интеграцию с операционной системой Windows. Frontend построен на стандартных веб-технологиях HTML5/CSS3/JavaScript с применением Canvas API для обработки изображений и WebSocket API для real-time обновлений.

## <a name="_цель"></a>**2.2 Цель разработки**

Целью разработки является создание кроссплатформенной системы управления и визуализации мультимедийного контента для стриминговых сервисов с автоматическим отображением информации о текущем воспроизводимом треке, обеспечивающей высокую производительность, гибкую настройку визуализации и бесшовную интеграцию с популярными стриминговыми приложениями.

**Анализ существующих решений и обоснование необходимости разработки.**

Анализ рынка программного обеспечения для отображения информации о музыке в стримах выявил ряд существенных проблем. Коммерческие решения (Streamlabs Ultra за $19/месяц, XSplit Broadcaster Premium за $25/месяц, Pretzel Rocks Pro за $15/месяц) требуют значительных финансовых затрат, что создает барьер для начинающих стримеров и студентов. Бесплатные альтернативы обладают ограниченной функциональностью: Snip поддерживает только Spotify без визуализации обложек, OBS Now Playing имеет базовый функционал без настройки внешнего вида.

Серьезной проблемой является высокая нагрузка на системные ресурсы. Многие программы используют неоптимизированные алгоритмы обработки изображений, что приводит к нагрузке на CPU в диапазоне 15-35% при обработке обложек и избыточному использованию оперативной памяти (более 300 МБ). Это негативно влияет на производительность стриминга и игр. Большинство решений работают только на Windows, ограничивая пользователей других операционных систем.

Индустрия стриминга демонстрирует динамичный рост. По данным Twitch Tracker (2024), на платформе Twitch зарегистрировано более 9.5 миллионов активных стримеров, YouTube Gaming насчитывает более 40 миллионов игровых каналов. Музыкальный контент играет ключевую роль: 78% стримеров используют фоновую музыку во время трансляций, 65% зрителей отмечают важность качественного аудиосопровождения. Интеграция музыки повышает вовлеченность аудитории на 23%.

Разработка NowPlay предоставит стримерам и контент-криейторам бесплатное, высокопроизводительное и функциональное решение с открытым исходным кодом, устраняя основные недостатки существующих аналогов.

# <a name="_назначение"></a>**3. Назначение разработки**

## <a name="_функциональное"></a>**3.1 Функциональное и эксплуатационное назначение программы**

Основной функцией программы NowPlay является автоматическое отображение информации о текущем воспроизводимом мультимедийном контенте в стриминговых приложениях и видеозаписях. Система осуществляет непрерывный мониторинг активных медиаплееров на компьютере пользователя, извлекает метаданные о воспроизводимых треках и автоматически загружает обложки альбомов из множественных источников, предоставляя визуальное представление этой информации через настраиваемые веб-виджеты.

Программа решает задачу информирования зрителей о музыкальном контенте, звучащем во время трансляции или в записанном видео, без необходимости ручного ввода данных стримером. Это позволяет зрителям узнавать названия понравившихся треков, повышает профессионализм оформления контента и улучшает взаимодействие между стримером и аудиторией. Система работает полностью автоматически, не требуя вмешательства пользователя после первоначальной настройки.

**Эксплуатационное назначение.**

Программа NowPlay предназначена для эксплуатации в трех основных режимах использования. Первый режим — интеграция с OBS Studio через Browser Source — является основным режимом работы для стримеров и контент-криейторов. Веб-виджет добавляется в сцену OBS как источник Browser Source, обеспечивая отображение информации о текущем треке непосредственно в трансляции.

Второй режим — standalone веб-интерфейс — предназначен для тестирования и предварительного просмотра виджетов перед добавлением в OBS, использования на втором мониторе для личного контроля воспроизводимой музыки, а также для разработки и отладки новых шаблонов визуализации.

Третий режим — desktop-приложение с графическим интерфейсом — является центром управления всей системой, предоставляя интуитивный интерфейс для конфигурации, управления сервером и настройки параметров визуализации.

## <a name="_сервисы"></a>**3.2 Краткое описание предоставляемых сервисов**

Система NowPlay предоставляет комплекс взаимосвязанных сервисов для обеспечения полного цикла обработки мультимедийной информации — от мониторинга медиаплееров до визуализации данных в стриминговых приложениях.

Сервис мониторинга медиаплееров обеспечивает автоматическое обнаружение воспроизведения музыки через Windows Media Control API с частотой опроса один раз в секунду, извлечение базовых метаданных непосредственно от медиаплеера и автоматическую инициацию загрузки обложки при смене трека.

Сервис получения метаданных и обложек предоставляет загрузку обложек альбомов с интеллектуальной приоритизацией источников и fallback-механизмами. Система использует иерархию источников (Windows Media Thumbnail API, Last.fm, iTunes, Yandex Music, VK Music) для обеспечения максимальной доступности обложек.

Встроенный асинхронный веб-сервер предоставляет RESTful API и WebSocket для real-time обновлений. Сервер работает на localhost, обеспечивая безопасность, и предоставляет endpoints для получения информации о текущем треке, обложки, обновления конфигурации и установки WebSocket соединений.

Сервис визуализации предоставляет четыре профессиональных шаблона с настраиваемым дизайном, автоматическим извлечением цветов из обложки, Ambient Light эффектом и плавными анимациями. Все шаблоны оптимизированы для различных сценариев использования.

Графический интерфейс управления обеспечивает современный desktop-интерфейс для управления конфигурацией системы, запуска/остановки сервера, настройки параметров визуализации и мониторинга статуса работы всех компонентов.

# <a name="_требования"></a>**4. Требования к программе**

## <a name="_функциональные"></a>**4.1 Требования к функциональным характеристикам**

Программный продукт должен предоставлять полный набор возможностей для автоматического мониторинга, обработки и визуализации информации о воспроизводимом мультимедийном контенте.

**Мониторинг медиаплееров.**

Система должна обеспечивать автоматический мониторинг медиаплееров через Windows Media Control API с частотой опроса 1 секунда. Компонент должен автоматически определять активную медиа-сессию, извлекать метаданные трека (исполнитель, название, альбом, длительность, текущая позиция, статус воспроизведения) и инициировать загрузку обложки при смене трека. Поддерживаются медиаплееры: Spotify, Apple Music, YouTube Music, VLC, Windows Media Player, Groove Music, AIMP, foobar2000, MusicBee и веб-браузеры (Chrome, Firefox, Edge, Opera).

**Получение обложек альбомов.**

Система должна загружать обложки с приоритизацией источников: Windows Media Thumbnail API, Last.fm API, iTunes Search API, Yandex Music API, VK Music API. При недоступности источника автоматически переключается на следующий. Если все источники недоступны — используется дефолтная обложка. Требования: максимальное время загрузки 3 секунды, форматы PNG/JPEG/WebP, размер 600x600 пикселей (минимум 300x300), максимальный размер файла 5 МБ.

**Веб-сервер и API.**

Встроенный асинхронный веб-сервер (aiohttp) работает на localhost:80. Предоставляет endpoints: POST /update_from_cs (обновления от C# компонента), GET /cover (получение обложки), GET /ws (WebSocket соединение), POST /update_config (обновление конфигурации), GET /sources (список источников), GET /{template}.html (шаблоны визуализации). WebSocket обеспечивает real-time коммуникацию с троттлингом обновлений (минимум 100 мс между сообщениями). Время отклика API менее 10 мс, задержка WebSocket менее 100 мс.

**Визуализация треков.**

Система должна предоставлять четыре профессиональных шаблона визуализации: вертикальный (300x400 пикселей), альтернативный (350x350 пикселей), минималистичный (250x80 пикселей), горизонтальный (600x120 пикселей). Все шаблоны должны поддерживать автоматическое извлечение доминирующих цветов из обложки, Ambient Light эффект (динамическая подсветка вокруг обложки), плавные CSS анимации и transitions, прозрачный фон для наложения на любой контент, адаптивное масштабирование текста при длинных названиях.

**Графический интерфейс.**

Desktop-приложение должно предоставлять современный интерфейс на базе CustomTkinter с поддержкой светлой и темной темы. Функционал: запуск/остановка сервера одной кнопкой, настройка порта и параметров визуализации, выбор активных источников обложек, отображение текущего трека и статуса системы, копирование URL виджетов для OBS, просмотр логов работы системы.

## <a name="_надёжность"></a>**4.2 Требования к надёжности**

Система должна обеспечивать стабильную работу в течение 24+ часов без перезапуска и деградации производительности. При сбое одного из компонентов (например, недоступность API источника обложек) система должна автоматически переключаться на альтернативные источники без прерывания работы. Все критические ошибки должны логироваться с указанием времени, компонента и описания проблемы.

Система должна корректно обрабатывать ситуации отсутствия интернет-соединения (использование кэшированных обложек), недоступности медиаплееров (переход в режим ожидания), некорректных метаданных (отображение "Unknown Artist" / "Unknown Title"). При критическом сбое компонента система должна автоматически перезапускать его с сохранением состояния.


## <a name="_производительность"></a>**4.3 Требования к производительности**

Система должна быть оптимизирована для минимальной нагрузки на системные ресурсы, чтобы не влиять на производительность стриминга и игр. Нагрузка на CPU должна составлять менее 2% при активном переключении треков и менее 0.5% в режиме ожидания. Использование оперативной памяти не должно превышать 200 МБ (Python компонент менее 150 МБ, C# компонент менее 50 МБ).

Время реакции на смену трека должно составлять менее 2 секунд от момента переключения в медиаплеере до обновления информации в веб-виджете. Загрузка обложки должна выполняться асинхронно и не блокировать обновление текстовой информации. Задержка WebSocket обновлений не должна превышать 100 мс.

Система должна эффективно использовать кэширование: обложки кэшируются на диске с автоматической очисткой старых файлов (максимум 500 МБ кэша), метаданные кэшируются в памяти для быстрого доступа, HTTP запросы к API используют connection pooling для снижения накладных расходов.

## <a name="_технические_средства"></a>**4.4 Требования к составу и параметрам технических средств**

Минимальные системные требования: операционная система Windows 10 (64-bit) версии 1903 или выше, Windows 11; процессор с тактовой частотой не менее 1.8 ГГц (рекомендуется 2.4 ГГц); оперативная память не менее 4 ГБ (рекомендуется 8 ГБ); свободное место на диске не менее 500 МБ для установки и 1 ГБ для кэша обложек; интернет-соединение для загрузки обложек (минимум 1 Мбит/с).

Программные требования: Python 3.12 или выше, .NET 6.0 Runtime или выше, современный веб-браузер (Chrome 90+, Firefox 88+, Edge 90+) для просмотра виджетов, OBS Studio 27.0+ или Streamlabs OBS для интеграции виджетов в трансляцию.

Поддерживаемые медиаплееры: любые приложения, использующие Windows Media Control API (Spotify, Apple Music, YouTube Music, VLC, Windows Media Player, Groove Music, AIMP, foobar2000, MusicBee, веб-браузеры с воспроизведением медиа).

## <a name="_совместимость"></a>**4.5 Требования к информационной и программной совместимости**

Система должна обеспечивать совместимость с OBS Studio 27.0+ и Streamlabs OBS через стандартный механизм Browser Source. URL виджетов должны иметь формат http://localhost:PORT/{template}.html, где PORT — настраиваемый порт (по умолчанию 80), template — имя шаблона (vertical, alternative, minimal, horizontal).

API должно предоставлять данные в формате JSON с кодировкой UTF-8. Структура ответа /update_from_cs должна включать поля: artist, title, album, duration, position, status, cover_url. WebSocket сообщения должны использовать тот же формат JSON.

Система должна поддерживать интеграцию с внешними API: Last.fm API v2.0, iTunes Search API, Yandex Music API (неофициальное), VK Music API. Все HTTP запросы должны использовать HTTPS для безопасности, таймаут запросов не более 5 секунд, автоматический retry при временных сбоях (максимум 3 попытки).

## <a name="_эргономика"></a>**4.6 Требования к эргономике и технической эстетике**

Графический интерфейс должен быть интуитивно понятным и не требовать специальных знаний для использования. Все элементы управления должны иметь понятные названия и подсказки. Интерфейс должен поддерживать светлую и темную темы с автоматическим переключением в зависимости от системных настроек.

Веб-виджеты должны иметь профессиональный дизайн с плавными анимациями и современной типографикой. Цветовая схема должна автоматически адаптироваться к обложке альбома для создания гармоничного визуального образа. Все шаблоны должны быть оптимизированы для различных разрешений экрана и корректно отображаться при масштабировании.

Текст в виджетах должен быть читаемым на любом фоне благодаря использованию теней и полупрозрачных подложек. При длинных названиях треков должно применяться адаптивное масштабирование шрифта или бегущая строка для обеспечения полной видимости информации.


## <a name="_эксплуатация"></a>**4.7 Требования к эксплуатации**

Установка должна выполняться через единый инсталлятор, автоматически устанавливающий все необходимые зависимости (Python, .NET Runtime, библиотеки). Первый запуск должен включать мастер настройки с пошаговыми инструкциями.

Программа должна автоматически запускаться при старте системы (опционально, настраивается пользователем) и работать в фоновом режиме с минимальным интерфейсом в системном трее. Пользователь должен иметь возможность быстро открыть главное окно, остановить/запустить сервер и скопировать URL виджетов через контекстное меню трея.

Система должна предоставлять подробную документацию: руководство пользователя с иллюстрациями, инструкцию по интеграции с OBS Studio, описание всех шаблонов визуализации и их настроек, FAQ с решением типичных проблем, документацию API для разработчиков.

Обновления программы должны устанавливаться автоматически или по запросу пользователя с сохранением всех настроек и кэша. Система должна уведомлять о доступности новых версий через интерфейс приложения.

## <a name="_защита"></a>**4.8 Требования к защите информации**

Система должна обеспечивать безопасность данных пользователя и защиту от несанкционированного доступа. Веб-сервер должен работать только на localhost (127.0.0.1) и не принимать подключения из внешней сети. Порт сервера должен быть настраиваемым для избежания конфликтов с другими приложениями.

API ключи для внешних сервисов (Last.fm, Yandex Music, VK) должны храниться в зашифрованном виде в конфигурационном файле. Система не должна собирать и передавать личные данные пользователя на внешние серверы без явного согласия.

Все HTTP запросы к внешним API должны использовать HTTPS для защиты данных при передаче. Система должна валидировать все входящие данные для предотвращения инъекций и других атак. Логи не должны содержать чувствительную информацию (API ключи, пароли).

Кэш обложек должен храниться в защищенной директории с ограниченным доступом. Система должна автоматически очищать временные файлы при завершении работы.
