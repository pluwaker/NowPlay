# Исправление конфигурации портов

## Проблема

MediaMonitor.exe имел жестко закодированный URL `http://localhost:8080`, в то время как Python сервер использовал функцию `find_free_port()`, которая искала свободный порт начиная с 8080. Если порт 8080 был занят, Python сервер запускался на следующем свободном порту (например, 8081), но MediaMonitor продолжал отправлять данные на порт 8080, что приводило к потере связи между компонентами.

## Решение

Реализована передача номера порта через аргументы командной строки.

**Обновление:** Порт по умолчанию изменен с 8080 на 58080 для избежания конфликтов с популярными приложениями.

### Изменения в C# коде

1. **MediaMonitor/Program.cs**
   - Добавлен парсинг аргумента `--port` или `-p`
   - Порт по умолчанию: 8080
   - Порт передается в конструктор MediaMonitor

2. **MediaMonitor/MediaMonitor.cs**
   - Конструктор теперь принимает параметр `port` (по умолчанию 8080)
   - URL Python сервера формируется динамически: `http://localhost:{port}`

### Изменения в Python коде

1. **ui/mediamonitor_manager.py**
   - Метод `start()` теперь принимает параметр `port`
   - Порт передается в MediaMonitor.exe через аргументы командной строки
   - Добавлено поле `self.port` для хранения текущего порта

2. **ui/app.py**
   - При запуске MediaMonitor передается актуальный порт сервера
   - `self.mediamonitor_manager.start(port=self.port)`

### Обновленные тесты

1. **tests/test_mediamonitor_manager.py**
   - Все существующие тесты обновлены для передачи параметра `port`
   - Добавлен новый тест `test_start_with_custom_port()` для проверки передачи кастомного порта

## Использование

### Запуск MediaMonitor вручную

```bash
# С портом по умолчанию (58080)
MediaMonitor.exe

# С кастомным портом
MediaMonitor.exe --port 58081
MediaMonitor.exe -p 58081
```

### Автоматический запуск через Python

MediaMonitor автоматически запускается с правильным портом при старте сервера через UI приложение.

## Тестирование

Все тесты успешно проходят:

```bash
python -m pytest tests/test_mediamonitor_manager.py -v
```

Результат: **12 passed in 0.72s**

## Совместимость

- Порт по умолчанию изменен с 8080 на 58080 для избежания конфликтов
- Если порт не указан, используется 58080
- Диапазон поиска свободных портов: 58080-59000
- Изменения не влияют на существующую функциональность
- Все существующие тесты обновлены и проходят успешно
