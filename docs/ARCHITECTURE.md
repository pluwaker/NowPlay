## Поток данных

### 1. Обнаружение нового трека

```
Windows Media API → C# MediaMonitor.Tick()
                    ↓
                    Сравнение artist/title
                    ↓
                    Новый трек обнаружен!
                    ↓
                    ┌─────────────────────┐
                    │ Параллельные задачи │
                    └─────────────────────┘
                    ↓                    ↓
            CoverFetcher.SaveCover()   WaitForDuration()
                    ↓                    ↓
            songinfo/cover.png      Duration получена
                    ↓                    ↓
                    └────────┬───────────┘
                             ↓
                    SendToPythonServer()
                             ↓
                    HTTP POST /update_from_cs
```

### 2. Обработка на Python сервере

```
POST /update_from_cs
        ↓
    Получение JSON
        ↓
    Обновление current_data
        ↓
    Проверка троттлинга (100ms)
        ↓
    Формирование сообщения
        ↓
    send_to_listeners()
        ↓
    ┌───────────────────┐
    │ Для каждого WS    │
    │ соединения:       │
    │ - Проверка живое  │
    │ - Отправка JSON   │
    │ - Удаление мертвых│
    └───────────────────┘
        ↓
    WebSocket клиенты получают обновление
```

### 3. Обновление позиции воспроизведения

```
C# MediaMonitor.Tick() (каждую секунду)
        ↓
    Получение timeline.Position
        ↓
    Изменение > 2 секунд?
        ↓ Да
    SendToPythonServer()
        ↓
    Python Server → WebSocket клиенты
```

## Компоненты и их ответственность

### C# MediaMonitor

| Компонент | Ответственность |
|-----------|----------------|
| `MediaMonitor.cs` | Основной цикл мониторинга, управление состоянием |
| `CoverFetcher.cs` | Загрузка и сохранение обложек |
| `CurrentMediaState.cs` | Модель данных о текущем треке |
| `Program.cs` | Точка входа, инициализация |

### Python Server

| Компонент | Ответственность |
|-----------|----------------|
| `update_from_cs()` | Прием данных от C# |
| `send_to_listeners()` | Рассылка обновлений по WebSocket |
| `websocket_handler()` | Управление WebSocket соединениями |
| `current_data` | Глобальное состояние системы |

## Оптимизации

### 1. Троттлинг обновлений
- Минимальный интервал: 100ms между обновлениями
- Предотвращает перегрузку WebSocket клиентов
- Реализовано в `send_to_listeners()`

### 2. Асинхронная обработка треков
- Загрузка обложки не блокирует основной поток
- Получение длительности в фоновом режиме
- Отмена предыдущих задач при смене трека

### 3. Очистка мертвых соединений
- Периодическая проверка WebSocket соединений
- Удаление закрытых соединений из списка
- Предотвращение утечек памяти

### 4. Кэширование конфигурации
- Перезагрузка конфига раз в 5 секунд
- Уменьшение операций чтения файла
- Кэширование `selected_media_source`

## Режимы работы

### Режим 1: C# MediaMonitor (рекомендуется)
```
use_builtin_monitor: false
```
- Только C# мониторинг
- Быстрая реакция
- Нативная работа с Windows API

### Режим 2: Python мониторинг
```
use_builtin_monitor: true
```
- Только Python мониторинг
- Без C# зависимостей
- Работает через winsdk

### Режим 3: Гибридный (не рекомендуется)
```
use_builtin_monitor: true + C# MediaMonitor запущен
```
- Оба мониторинга активны
- Возможны дублирования
- Для отладки и сравнения

## Масштабируемость

### Текущие ограничения
- Один источник медиа (можно выбрать через `selected_media_source`)
- Локальный сервер (localhost)
- Без аутентификации

### Возможные улучшения
- Поддержка нескольких источников одновременно
- Удаленный доступ через HTTPS
- Аутентификация через токены
- Кластеризация для высокой нагрузки
- Кэширование обложек в памяти
- Поддержка Redis для распределенного состояния
