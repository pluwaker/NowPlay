# Исправление обнаружения источников медиа

## Проблема

При запуске MediaMonitor консоль выдавала "Обнаружено 0 источников", даже если медиаплеер уже воспроизводил музыку. При автоматическом переключении трека также выводилось "Получено 0 источников от C# MediaMonitor". Источники появлялись только после ручного переключения трека.

### Причины

**Проблема 1: Создание нового SessionManager**

Метод `SendAvailableSources()` создавал **новый** `SessionManager` каждый раз:
```csharp
var manager = await GlobalSystemMediaTransportControlsSessionManager.RequestAsync();
var sessions = manager.GetSessions();
```

Новый менеджер не успевал получить актуальный список сессий, особенно при автоматическом переключении трека.

**Проблема 2: Недостаточные задержки**

При старте MediaMonitor и при событии `SessionsChanged`:
1. Windows Media API мог еще не успеть инициализировать сессии
2. Медиаплеер мог находиться в процессе запуска
3. `GetSessions()` возвращал пустой список

При ручном переключении трека пользователь давал системе время на обновление, поэтому источники обнаруживались.

## Решение

Реализованы три ключевых исправления:

### 0. Использование существующего SessionManager (ГЛАВНОЕ ИСПРАВЛЕНИЕ)

```csharp
// БЫЛО: Создавали новый менеджер каждый раз
var manager = await GlobalSystemMediaTransportControlsSessionManager.RequestAsync();
var sessions = manager.GetSessions();

// СТАЛО: Используем существующий менеджер
if (sessionManager == null)
{
    Console.WriteLine("⚠️ SessionManager не инициализирован");
    return;
}
var sessions = sessionManager.GetSessions();
```

**Почему это важно:**
- Существующий `sessionManager` уже подписан на события и имеет актуальную информацию
- Создание нового менеджера требует времени на инициализацию
- Новый менеджер может не "видеть" сессии, которые находятся в процессе переключения

Это **главное** исправление, которое решает проблему с автоматическим переключением треков.

### Дополнительные меры для надежности:

### 1. Начальная задержка (500ms)

```csharp
// Даем время медиаплееру инициализироваться перед первой отправкой источников
await Task.Delay(500);

// Отправляем начальный список источников
await SendAvailableSources(force: true);
```

Небольшая задержка дает Windows Media API время для инициализации сессий.

### 1.1. Задержка в обработчике SessionsChanged (300ms)

```csharp
private async void OnSessionsChanged(...)
{
    // Даем время сессиям обновиться перед отправкой списка источников
    await Task.Delay(300);
    
    await SendAvailableSources(force: true);
    ...
}
```

Когда происходит автоматическое переключение трека, событие `SessionsChanged` срабатывает раньше, чем сессии успевают обновиться. Задержка 300ms решает эту проблему.

### 2. Повторная отправка через 3 секунды

```csharp
// Повторно отправляем источники через 3 секунды на случай если медиаплеер запустится позже
_ = Task.Run(async () =>
{
    await Task.Delay(3000);
    await SendAvailableSources(force: true);
});
```

Если медиаплеер запустится после старта MediaMonitor, источники будут обнаружены при повторной проверке.

### 3. Улучшенное логирование

```csharp
Console.WriteLine($"🔍 Поиск источников... Найдено сессий: {sessions.Count}");
```

Теперь в консоли видно, сколько сессий было найдено, что помогает диагностировать проблемы.

## Результат

Теперь источники обнаруживаются надежно в следующих сценариях:

✅ **Медиаплеер уже запущен** - обнаруживается после 500ms задержки
✅ **Медиаплеер запускается одновременно** - обнаруживается при повторной проверке через 3 секунды
✅ **Медиаплеер запускается позже** - обнаруживается при событии `SessionsChanged`
✅ **Переключение трека** - обнаруживается при событии `SessionsChanged`

## Тестирование

### Сценарий 1: Медиаплеер уже запущен
1. Запустите медиаплеер (Spotify, VLC, и т.д.)
2. Начните воспроизведение
3. Запустите MediaMonitor
4. **Ожидаемый результат:** Источники обнаружены в течение 1 секунды

### Сценарий 2: Медиаплеер запускается после MediaMonitor
1. Запустите MediaMonitor
2. Запустите медиаплеер
3. Начните воспроизведение
4. **Ожидаемый результат:** Источники обнаружены в течение 3-4 секунд

### Сценарий 3: Переключение трека
1. Запустите MediaMonitor с работающим медиаплеером
2. Переключите трек
3. **Ожидаемый результат:** Источники обновляются мгновенно

## Технические детали

### Изменения в коде

**Файл:** `MediaMonitor/MediaMonitor.cs`

**Метод:** `SendAvailableSources()` ⭐ ГЛАВНОЕ ИСПРАВЛЕНИЕ
1. **Используется существующий `sessionManager` вместо создания нового**
2. Добавлена проверка на null
3. Добавлено логирование количества найденных сессий

**Метод:** `Start()`
4. Добавлена задержка 500ms перед первой отправкой источников
5. Добавлена асинхронная задача для повторной отправки через 3 секунды

**Метод:** `OnSessionsChanged()`
6. Добавлена задержка 300ms перед отправкой источников при изменении сессий

### Почему именно эти значения?

- **500ms** (начальная задержка) - достаточно для инициализации Windows Media API, но не заметно для пользователя
- **300ms** (при изменении сессий) - минимальная задержка для обновления сессий при переключении трека
- **3 секунды** (повторная проверка) - достаточно для запуска большинства медиаплееров, но не слишком долго

### Альтернативные решения (не реализованы)

1. **Polling каждые N секунд** - избыточная нагрузка на систему
2. **Увеличение начальной задержки** - ухудшает UX
3. **Только событие SessionsChanged** - не работает если медиаплеер уже запущен
