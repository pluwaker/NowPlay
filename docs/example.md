# <a name="_toc216052823"></a>**1. Введение**
## <a name="_toc216052824"></a>**1.1 Наименование разработки.**
Веб-сервис сервис практики быстрой печати и печати вслепую, который представляет из себя веб-приложение, предназначенное для индивидуальной тренировки навыков слепой печати и повышения скорости набора текста.
## <a name="_toc216052825"></a>**1.2 Область применения программы**
Программный продукт предназначен для личного использования отдельными пользователями - энтузиастами, специалистами и разработчиками, которые хотят самостоятельно тренировать навык быстрой и точной печати. Сервис рассчитан на индивидуальных пользователей, предпочитающих персонализированные тренировки, приватное хранение истории и личные настройки упражнений, а также на тех, кто использует приложение как инструмент самосовершенствования вне рамок формальных образовательных учреждений. В отличие от корпоративных или учебных решений, основной акцент сделан на простоте развёртывания для одного пользователя, приватности данных и удобстве ежедневного использования на личных устройствах.

**1.3 Краткая характеристика области применения и целевой аудитории.**

Целевой аудиторией сервиса являются один пользователь или небольшая группа близких пользователей, использующая сервис для индивидуальных тренировок и отслеживания прогресса. Среди предполагаемых пользователей — начинающие и опытные печатники, айтишники и программисты, желающие увеличить скорость ввода кода, копирайтеры и менеджеры, для которых важна скорость набора, а также все, кто хочет выработать навык печати вслепую для личного развития. Сервис предоставляет персональные режимы тренировки (по количеству слов, по времени, тематические наборы и режим печати кода с выбором языка), индивидуальные настройки сложности и конфиденциальную статистику в профиле — графики прогресса, личные рекорды и локальные лидерборды, повышающие мотивацию, но ориентированные на приватное пользование.

## <a name="_toc216052828"></a>**2.2 Анализ аналогов и обоснование необходимости разработки.**
Анализ существующих онлайн-тренажёров показал наличие множества сервисов, ориентированных на массовых пользователей и учебные группы: они предлагают базовые режимы по времени или количеству знаков и общую статистику. Для личного пользователя такие решения часто оказываются избыточными по функционалу, недостаточно приватными или не учитывают индивидуальных сценариев тренировки, особенно когда речь идёт о практике набора программного кода с выбором языка. Предлагаемый продукт обосновывается необходимостью иметь лёгкий в развёртывании и конфигурируемый инструмент, который фокусируется на персональных настройках, приватности данных, детальной пер-пользовательской аналитике и режиме печати кода. Реализация на Next.js + PostgreSQL обеспечивает удобство локального/облачного развёртывания, гибкость в управлении библиотекой упражнений и сохранении истории одного пользователя, что закрывает выявленные потребности и делает проект ценным именно для персонального использования.
# <a name="_toc216052829"></a>**3. Назначение разработки**
## <a name="_toc216052830"></a>**3.1 Функциональное назначение.** 
Сервис предназначен для предоставления индивидуальному пользователю набора инструментов для организации и проведения тренировок по быстрой печати и печати вслепую. Ключевые функции включают выбор режима тренировки (по количеству слов, по времени, режим цитат и режим практики кода с возможностью выбора языка программирования), гибкую настройку параметров сессии (количество слов, продолжительность, источник текста, уровень сложности), генерацию и отображение упражнений, а также автоматический подсчёт и сохранение метрик — скорость, точность (процент ошибок), распределение ошибок по клавишам и словам. Пользовательский профиль хранит историю занятий, персональные рекорды и визуализации прогресса. Дополнительно сервис имеет таблицы лидеров и достижения, направленные на повышение мотивации в рамках личного использования.
## <a name="_toc216052831"></a>**3.2 Эксплуатационное назначение.** 
Программный продукт эксплуатируется как персональное веб-приложение, доступное через современный браузер на личных устройствах пользователя (настольный ПК, ноутбук, при частичном удобстве — планшет). Для типичного сценария эксплуатации достаточно иметь браузер и клавиатуру; серверную часть можно разместить на личном хостинге, VPS или использовать бесплатные/платные облачные площадки. 

С учётом фокуса на одного пользователя, требования к серверным ресурсам невелики, но предусмотрены механизмы резервного копирования и экспорта данных для сохранности личной истории занятий. Администрирование сведено к минимуму — пользователь сам управляет своей библиотекой упражнений и настройками приватности.
## <a name="_toc216052832"></a>**3.3 Краткое описание предоставляемых сервисов и сценариев использования.**
Пользователь начинает с главной страницу с выбором режима тренировки: «по количеству слов», «по времени» или «практика программного кода». Для каждого режима доступны интуитивные настройки — число слов, длительность сессии или подборка текстов/языков программирования. Во время сессии система в реальном времени считает скорость и точность, а по окончании предоставляет детализированный отчёт и рекомендации. 

Также, пользователь может перейти на страницу регистрации и создать новый аккаунт. В случае, если пользователь уже имеет зарегистрированный аккаунт, то он может перейти на страницу персонального профиля, где пользователь может просматривать историю своих сессий печати, видеть личную статистику и графики прогресса. Социальные элементы (таблицы лидеров, сравнение результатов) реализованы в рамках общедоступных списков для поддержки мотивации, при этом основной сценарий использования остаётся индивидуальным и ориентирован на сохранение приватности данных.
# <a name="_toc216052833"></a>**4. Требования к программе (программному изделию).**
## <a name="_toc216052834"></a>**4.1 Функциональные требования.**
Программный продукт должен предоставлять пользователю полный набор возможностей для организации и проведения персональных тренировок по набору текста и набору программного кода. На главной странице пользователь выбирает режим тренировки — «по количеству слов», «по времени», «цитаты» или «режим программирования» — и задаёт параметры сессии: количество слов или продолжительность, язык и набор текстов (включая выбор языка программирования для режима программирования), а также дополнительные опции. Генерация тренировки должна корректно учитывать выбранные настройки: формировать последовательность слов заданной длины, подбирать фрагменты цитат и программного кода с сохранением форматирования, отступов и специальных символов.

Во время сессии интерфейс обеспечивает автоматическую обработку ввода в реальном времени: подсвечивает текущий символ/слово, отмечает ошибки (включая подсказку по клавишам при желании), и отображает ключевые показатели — скорость (WPM), точность в процентах, количество ошибок и количество ошибок. По окончании сессии система формирует детализированный отчёт, сохраняет результаты в профиле пользователя и предоставляет визуализации прогресса (график WPM по времени, история результатов, heatmap ошибок по клавишам). Для режима программирования дополнительно фиксируются ошибки, связанные с неверным набором спецсимволов и нарушением отступов, и эти данные включаются в отчёт.

Пользовательский профиль содержит персональные настройки, историю всех сессий, список собственных наборов, личные рекорды по каждому режиму и достижения. Предусмотрены механизмы таблиц лидеров и списков сравнения с друзьями.
## <a name="_toc216052835"></a>**4.2 Требования к надёжности и восстановлению.**
Сервис должен устойчиво работать при типичных пользовательских сценариях и корректно обрабатывать сбои сети и ошибки клиента. Каждая сессия периодически сохраняет промежуточное состояние (например, в локальное хранилище и/или на сервер) с минимальным интервалом (каждые 3–5 секунд либо при существенном событии), чтобы при потерях соединения или случайном закрытии вкладки пользователь мог восстановить сессию без потери точности результатов. Вся критичная информация (пользовательские данные, история сессий, библиотека упражнений) хранится в PostgreSQL с настроенной политикой бэкапов: ежедневное резервное копирование с возможностью восстановления за последние 7 дней как минимум, а также документированная процедура экспорта/импорта данных для аварийного восстановления.

Логирование должно покрывать ошибки серверной и клиентской частей, исключения, попытки аутентификации и события сохранения/удаления данных. Логи защищены от несанкционированного доступа и подлежат ротации; для частного развёртывания достаточно файловых логов с ротацией, для облачных развёртываний возможна опциональная интеграция с внешними сервисами логирования.
## <a name="_toc216052836"></a>**4.3 Требования к производительности и масштабируемости**
Ключевой характеристикой качества является минимальная задержка обработки ввода: реакция интерфейса на нажатие клавиши и обновление состояния сессии должны происходить в пределах 50-100 мс на клиентском устройстве, так как именно это обеспечивает корректность измерений скорости и точности. Серверные операции, влияющие на UX (загрузка упражнений, сохранение сессии, запрос профиля), должны выполняться в пределах 1-2 секунд при нормальных условиях сети. Генерация сессии (подбор текста или сборка фрагмента кода) должна занимать не более 500-1000 мс на стороне сервера; при выполнении генерации на клиенте - не более 100-200 мс.

Архитектура приложения проектируется с возможностью горизонтального масштабирования: клиентская часть на Next.js и API на Node.js/Serverless допустимо разворачивать в нескольких экземплярах за балансировщиком, база данных PostgreSQL - с поддержкой репликации и резервирования. Для персонального развёртывания минимально необходимы ресурсы уровня одноядерного процессора с тактовой частотой не менее 1.8 ГГц и 1-2 ГБ оперативной памяти. Для профессионального облачного развёртывания рекомендуется двухъядерный процессор с тактовой частотой не менее 2.2 ГГц и 4 ГБ оперативной памяти с SSD-диском объёмом не менее 12 ГБ.
## <a name="_toc216052837"></a>**4.4 Требования к составу и параметрам технических средств.**
Клиентская часть должна корректно работать в современных версиях браузеров: Chrome, Firefox, Edge и Safari (две последние мажорные версии), на настольных и ноутбуковых платформах с полноразмерной клавиатурой; мобильная поддержка реализуется с оглядкой на ограничение удобства ввода с виртуальной клавиатуры. Серверная часть требует Node.js 18+ и PostgreSQL 12+. Все зависимости и версии библиотек документируются в составе проекта. Развёртывание и сборка обеспечиваются стандартными инструментами (npm/yarn, сборка Next.js), репозиторий хранится в системе контроля версий (Git) с инструкцией по CI/CD и миграциям БД.
## <a name="_toc216052838"></a>**4.5 Требования к информационной и программной совместимости.**
API предоставляет REST-эндпоинты, возвращающие структурированные JSON-ответы (описание формата результатов: идентификатор сессии, userId, режим, длительность, общее число символов, число ошибок, WPM/CPM, временная метка, дополнительные метаданные). Для взаимодействия с внешними сервисами (например, отправка писем для восстановления пароля) используется HTTPS API. ORM (в данном случае Prism) и схема БД документируются и снабжаются миграциями.
## <a name="_toc216052839"></a>**4.6 Требования к эргономике интерфейса и пользовательскому опыту.**
Интерфейс проектируется с приоритетом на минималистичность и фокус на тексте - элементы интерфейса, не связанные с набором, скрываются или приглушаются во время сессии. Все основные действия (старт/пауза/рестарт/завершение) доступны с клавиатуры. Предусмотрены горячие клавиши (например, первый ввод запускает сессию, Tab - перезапуск, Escape - закрытие модального окна с результатами), возможность изменения размера шрифта, выбора контрастной темы и отключения анимаций. Для режима программирования особое внимание уделяется корректному отображению и вводу символов, таких как скобки, кавычки, двоеточия и табуляции. При необходимости предоставляются подсказки, и опция «игнорировать отступы» для адаптации под разные цели тренировки. Интерфейс локализован на русский и английский языки с возможностью расширения.
## <a name="_toc216052840"></a>**4.7 Требования к безопасности и приватности.**
Приложение обязано использовать защищённый канал связи (HTTPS, TLS 1.2+). Пользовательские пароли хранятся в базе в форме надёжных хешей, токены и cookie имеют флаги HttpOnly и Secure, применяется защита от CSRF и XSS, ввод проверяется на клиенте и обязательно на сервере. Публикация результатов, участие в глобальных таблицах лидеров и обмен данными с третьими лицами допускаются только при явном согласии пользователя. Для обеспечения конфиденциальности реализовано удаление аккаунта и экспорт всех данных пользователя по запросу. Бэкапы данных хранятся зашифровано.
## <a name="_toc216052841"></a>**4.8 Требования к тестируемости и критериям приёмки.**
Каждое требование должно иметь соответствующий набор тестовых сценариев: позитивные сценарии, граничные условия и сценарии отказа (потеря сети, некорректные форматы импорта, проблемы авторизации). # **8. Порядок контроля и приёмки**
## **8.1 Виды тестирования**
Приёмка программного изделия проводится на основе комплекса типов тестирования, покрывающего как функциональные, так и нефункциональные требования:

Функциональные тесты - юнит-тесты и интеграционные тесты, проверяющие корректность вычислений, генерацию и подбор текстов, работу режимов и API для сохранения/получения результатов. 

End-to-end тесты - автоматизированные и ручные сценарии, воспроизводящие полные пользовательские пути: регистрация/вход, запуск сессии в каждом режиме, ввод текста, завершение и просмотр отчёта, работа профиля и просмотр истории.

Тесты надёжности и устойчивости - проверки восстановления сессии при разрыве сети, корректное сохранение промежуточного состояния, устойчивость к повторным запросам и корректная реакция на отказ БД/серверной части.

Тесты производительности - измерение времени отклика UI на ввод (целевой порог ≤ 100 мс), время ответа серверных эндпоинтов (целевой порог ≤ 2 с) и время генерации сессии.

Тесты безопасности - проверки соответствия базовым требованиям безопасности: наличие HTTPS, хеширование паролей, защита от CSRF и XSS, корректная валидация входных данных, отсутствие утечек чувствительных данных в логах; по необходимости - сканирование зависимостей на известные уязвимости.

Юзабилити-тестирование — ручное тестирование удобства запуска и прохождения сессии, корректности отображения режима программирования и локализаций, а также тестирование базовых сценариев.
## **8.2 Методика проверки и используемые тестовые сценарии**
Приёмочные испытания выполняются в выделенной тестовой среде, максимально приближённой к целевому окружению развёртывания (Node.js, PostgreSQL, HTTPS). Для воспроизводимости все тестовые данные и шаги фиксируются. Автоматизированные тесты запускаются в CI, ручные - по заранее утверждённому плану тестирования. Основные этапы методики:

1. Подготовка окружения - развёртывание релиза в тестовом окружении, загрузка контрольных наборов упражнений и тестовых аккаунтов, настройка логирования и бэкапов.
1. Запуск автоматизированного набора тестов. Ожидается 100% прохождение критичных модулей. При обнаружении регрессий релиз откатывается до фикса багов.
1. Выполнение E2E-сценариев вручную. Каждый сценарий сопровождается чек-листом «шаг — ожидаемый результат — фактический результат».

Основной набор используемых тестовых сценариев:

Сценарий «Нормальная тренировка». Предусловие: авторизованный/гостевой пользователь, выбран режим «слова», лимит 50 слов. Шаги: старт сессии, ввод корректного текста, допущение N ошибок, завершение. Ожидаемый результат: расчёт параметров в соответствии с формулами, сохранение сессии в истории, корректная визуализация отчёта.

Сценарий «Нормальная тренировка — Time». Предусловие: выбран режим «время», 60 секунд. Шаги: старт, набор в течение 60 секунд, автоматическое завершение. Ожидаемый результат: корректное измерение параметров с учётом ошибок, отображение ошибок и подсказок.

Сценарий «Code Mode — спецсимволы и отступы». Предусловие: выбран язык (например, Python), фрагмент содержит табы/пробелы и скобки. Шаги: набор кода с ошибками в отступах, завершение. Ожидаемый результат: система фиксирует ошибки спецсимволов и отступов, отчёт отражает тип ошибок; визуализация кода сохраняет форматирование.

Сценарий «Аутентификация и сохранение результатов». Предусловие: учетная запись существует. Шаги: вход, запуск сессии, завершение, проверка сохранённой записи в БД и отображение в профиле. Ожидаемый результат: данные корректно записаны в БД, профиль отображает историю и рекорды.
